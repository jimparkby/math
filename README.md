# GeoPath — поиск оптимальных маршрутов на графе дорожной сети Минска

Практическая часть статьи «Использование методов компьютерного моделирования для решения задач теории графов: алгоритмы поиска кратчайшего пути» (БНТУ, конференция DIGITAL-2027).

**Онлайн-версия:** <https://math-mauve-eight.vercel.app/> · исходный код: <https://github.com/jimparkby/math>

Все алгоритмы поиска пути реализованы самостоятельно (без готовых маршрутизаторов): Дейкстра, A*, двунаправленная Дейкстра, Беллман — Форд, Флойд — Уоршелл. Карта: Mapbox GL JS v3, данные дорожной сети: OpenStreetMap.

## Запуск

1. Откройте `index.html` двойным щелчком (сервер и сборка не нужны). Сайт также можно опубликовать как статический (Vercel, GitHub Pages).
2. При первом запуске введите **публичный токен Mapbox** (`pk.…`). Он сохраняется только в `localStorage` этого браузера. Можно вписать его и в `js/config.js` (`MAPBOX_TOKEN`).
3. Без токена или без интернета карта недоступна, но математическая часть работает: построение маршрута по готовым сценариям, таблица сравнения, эксперимент, самопроверка, учебный пример.

### Как получить токен Mapbox и ограничить его

1. Зарегистрируйтесь на <https://account.mapbox.com/> и откройте **Access tokens → Create a token** (достаточно публичных scope по умолчанию).
2. Токен виден в коде страницы, поэтому для опубликованного сайта задайте **URL restrictions**, например `https://<ваш-проект>.vercel.app`.
3. Учтите, что токен с URL-ограничением **не работает при открытии через `file://`**: браузер не передаёт адрес страницы (Referer). Для локальной демонстрации используйте отдельный токен без ограничений или откройте страницу через локальный сервер (`python -m http.server`) и добавьте `http://127.0.0.1:8000` в список разрешённых адресов.
4. Бесплатного лимита Mapbox (50 000 загрузок карты в месяц) для демонстрации хватает с запасом.

```bash
node tools/run_experiment.js 100 dist
node tools/run_experiment.js 100 time
```

## Математическая модель

- **Граф** — ориентированный взвешенный `G = (V, E, w)`, `w : E → ℝ≥0`. Двусторонняя улица даёт две противоположные дуги, односторонняя (`oneway=yes|1|true|-1|reverse`, кольца `junction=roundabout|circular`, `highway=motorway`) — одну.
- **Дороги**: `highway` ∈ {motorway, trunk, primary, secondary, tertiary (+ `_link`), unclassified, residential, living_street}; исключаются `access=no|private`, `motor_vehicle=no|private`, `area=yes`.
- **Расстояние** — формула гаверсинусов, `R = 6 371 008,8 м`; длина дуги — сумма длин её отрезков. Координаты хранятся с точностью 6 знаков, длины вычисляются по округлённым координатам и округляются **вверх** до 1 мм. Поэтому вес дуги не меньше длины дуги большого круга между её концами, и эвристика A* остаётся допустимой.
- **Время** `t = d / v`: `v` = `maxspeed` (≤ 110 км/ч), иначе типовая скорость (допущение модели, км/ч):

  | класс | км/ч | класс | км/ч |
  |---|---|---|---|
  | motorway | 90 | motorway_link, trunk_link | 40 |
  | trunk | 70 | primary_link, secondary_link | 35 |
  | primary | 60 | tertiary_link | 30 |
  | secondary | 50 | unclassified | 30 |
  | tertiary | 40 | residential | 25 |
  | | | living_street | 10 |

- При построении проверяется, что все веса неотрицательны (иначе исключение).
- **Упрощение**: узел с двумя отрезками к разным соседям, одинаковой скоростью и согласованным направлением удаляется, дуги сливаются, веса складываются.
- **Связность**: итеративный алгоритм Тарьяна, остаётся наибольшая компонента сильной связности.
- **Хранение**: CSR, `(|V|+1)·4 + |E|·20` байт.

### Обоснование A*

- Эвристика: для расстояния `h(v) = hav(v, t)`, для времени `h(v) = hav(v, t) / v_max`, где `v_max` — максимальная скорость среди дуг графа (90 км/ч на снимке).
- **Допустимость:** `h(v)` не больше истинной оставшейся стоимости, потому что дорога не короче дуги большого круга, а ехать быстрее `v_max` нельзя. Значит, A* находит оптимальный путь.
- **Согласованность:** `h(u) ≤ w(u,v) + h(v)` по неравенству треугольника. Поэтому каждая вершина обрабатывается не более одного раза, и A* обрабатывает подмножество вершин, которые обрабатывает Дейкстра.
- Дейкстра — частный случай A* при `h ≡ 0` (в коде одна функция). Для запаса на погрешность IEEE-754 эвристика умножается на `1 − 10⁻⁹`; на оптимальность это не влияет.

### Счётчики и замер времени

- **Обработано вершин** — извлечены из кучи окончательно.
- **Релаксации** — просмотренные дуги (проверки `d(u) + w(u,v) < d(v)`).
- **Операции с кучей** — push + pop.
- **Время вычисления** — серии запусков, каждая не короче 30 мс, после прогрева. В интерфейсе берётся медиана по 5 сериям, в эксперименте минимум по 3. Это время работы алгоритма, а не время поездки.

### Ограничения

- В подграф для Флойда — Уоршелла (радиус 500 м) попадает лишь 15–40 вершин: после упрощения сеть Минска разреженная (≈ 7,4 тыс. перекрёстков). Предел в 400 вершин на практике не достигается.
- Время поездки — модельное (свободный поток, без светофоров, пробок и штрафов за повороты), поэтому оно меньше оценок навигационных сервисов. Сверка с Mapbox Directions в интерфейсе служит только внешней оценкой.

## Архитектура (для статьи)

Схема: OpenStreetMap (Overpass API) → построение графа (фильтрация, веса, упрощение) → наибольшая SCC (Тарьян) → CSR → алгоритмы (Дейкстра, A*, двунаправленная Дейкстра, Беллман — Форд, Флойд — Уоршелл) → визуализация Mapbox GL JS.

Описание. Дорожная сеть Минска загружается из OpenStreetMap через Overpass API и преобразуется скриптом на Python в ориентированный взвешенный граф. Односторонние улицы учитываются направлением дуг. Каждая дуга получает два веса: длину по формуле гаверсинусов и время проезда по разрешённой или типовой скорости. Промежуточные узлы, задающие только форму улиц, сжимаются, так что вершины графа соответствуют перекрёсткам. Затем алгоритм Тарьяна выделяет наибольшую компоненту сильной связности. Граф хранится в браузере в виде списка смежности в формате CSR на типизированных массивах. Поиск пути выполняют собственные реализации алгоритмов на двоичной куче со счётчиками операций. Корректность подтверждена сверкой с библиотекой NetworkX и взаимной сверкой алгоритмов. Результаты отображаются на карте Mapbox GL JS, а вычислительный эксперимент экспортируется в CSV и в таблицу для статьи.
